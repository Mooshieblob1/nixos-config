# nixos-config

A flake-based NixOS configuration you can use as a starting point for your own desktop machine. It targets a single host but is written to be read and adapted, not just cloned.

## What you get

- **Flake-based**, with `nixpkgs` pinned to an exact revision so builds are reproducible and package updates are deliberate.
- **home-manager** integrated as a NixOS module, so one rebuild builds the system and the user's home together.
- **Secure Boot** via [lanzaboote](https://github.com/nix-community/lanzaboote), with keys managed by `sbctl`.
- **Two desktops:** GNOME on Wayland (GDM) plus a Hyprland session selectable at login.
- **NVIDIA** on the open kernel modules, with VRAM-preserving suspend/resume (needed for RTX 50-series / Blackwell).
- **PipeWire** audio (ALSA + Pulse compat), PulseAudio disabled.
- **Quality-of-life defaults:** fish shell, direnv + nix-direnv, automatic weekly garbage collection, store auto-optimise, NTFS/ext4 data-drive automounts, flat mouse acceleration.

## Before you build: what to change

This config is written for one machine and one user, so it will not build as-is on yours. Change at least these:

- **Hardware.** Delete `hardware-configuration.nix` and regenerate it with `sudo nixos-generate-config`. The filesystem and swap UUIDs in `configuration.nix` (the `fileSystems."/mnt/*"` and `swapDevices` blocks) point at specific disks and will not match yours. Edit or remove them.
- **User.** The user is `blob`. Rename it in `configuration.nix` (`users.users."blob"`), `flake.nix` (`home-manager.users.blob`), and `home.nix` (`home.username`, `home.homeDirectory`). Set your own `userName` and `userEmail` in `home.nix`'s `programs.git`.
- **Hostname.** It is `nixos`. Change `networking.hostName` in `configuration.nix` and the `nixosConfigurations.nixos` output name in `flake.nix`. Keep the two matching so `nixos-rebuild` auto-detection works.
- **GPU.** The NVIDIA block targets an RTX 5070 (Blackwell) using the open kernel modules. For other hardware, adjust or remove `services.xserver.videoDrivers` and `hardware.nvidia`.
- **Secure Boot.** lanzaboote needs its own signing keys generated with `sbctl` (see the comments in `configuration.nix`). If you do not want Secure Boot, drop the `lanzaboote` input from `flake.nix` and re-enable `boot.loader.systemd-boot`.
- **Locale, timezone, keymap.** Set for Australia (`Australia/Perth`, `en_GB` / `en_AU`, `au` keymap). Change to your region.

## Building

Put the config at `/etc/nixos/`, then:

```bash
# Apply the new config and make it the default boot generation.
sudo nixos-rebuild switch

# Apply without making it default (reverts on reboot). Use when unsure.
sudo nixos-rebuild test

# Evaluate and build without activating, to catch errors early.
sudo nixos-rebuild build

# Roll back to the previous generation if something breaks.
sudo nixos-rebuild switch --rollback
```

If the flake lives at `/etc/nixos/` and its output name matches your hostname, `nixos-rebuild` auto-detects it. Otherwise pass it explicitly:

```bash
sudo nixos-rebuild switch --flake /etc/nixos#<your-hostname>
```

## Repo layout

| File | Purpose |
| --- | --- |
| `flake.nix` | Entry point. Defines the `nixosConfigurations` output, pins `nixpkgs`, and wires in the `lanzaboote` and `home-manager` inputs. |
| `flake.lock` | Locks the resolved revisions of every flake input. |
| `configuration.nix` | The main file. System packages, services, users, locale, desktop, bootloader, drives. |
| `hardware-configuration.nix` | Machine-specific, generated by `nixos-generate-config`. Regenerate it for your hardware. |
| `home.nix` | home-manager config for the user (direnv, git). Applied as part of the system rebuild. |

## Updating packages

`nixpkgs` is pinned in `flake.nix`, so a plain rebuild will not pull newer packages. To move versions:

```bash
nix flake update            # all inputs
nix flake update nixpkgs    # just one
sudo nixos-rebuild switch
```

Find a package name before adding it with `nix search nixpkgs <name>`.

## Adding packages

- System-wide packages go in `environment.systemPackages` in `configuration.nix`.
- Per-user packages go in `users.users."<name>".packages`.
- Prefer `services.<name>.enable = true;` over hand-wiring systemd units.
- Flakes only evaluate git-tracked files. After creating a **new** file, `git add` it before rebuilding, or evaluation fails with `path '...' does not exist`.

## Hyprland rice and dotfiles

This config installs the Hyprland toolkit (waybar, wofi, eww, hyprlock, hypridle, wallust, fish, and friends) but only the packages. The actual configs for those live in a separate dotfiles repo, managed with GNU stow:

**https://github.com/Mooshieblob1/dotfiles**

Install the system side from here, then apply that repo if you want the matching desktop theming.
