# nixos-config

Flake-based NixOS configuration for a single machine: hostname `nixos`, primary user `blob`.

This repo lives at `/etc/nixos/` on the running system and is version-controlled with git (remote: `github.com/Mooshieblob1/nixos-config`). Editing a file here and rebuilding is how the OS is changed; nothing is configured imperatively.

## Quick start

Everything flows through `nixos-rebuild`. Edit a file, then:

```bash
# Apply the new config now and make it the default boot generation.
sudo nixos-rebuild switch

# Apply without making it the default (reverts on reboot). Use when unsure.
sudo nixos-rebuild test

# Evaluate and build without activating, to catch errors early.
sudo nixos-rebuild build

# Revert to the previous generation if something breaks.
sudo nixos-rebuild switch --rollback
```

Because the flake lives at the default path `/etc/nixos/` and its output name (`nixos`) matches the hostname, `nixos-rebuild` auto-detects it. You do not need to pass `--flake`. The explicit form is `--flake /etc/nixos#nixos`.

A single `switch` builds both the system and user `blob`'s home-manager generation, since home-manager is wired in as a NixOS module. There is no separate `home-manager switch`.

## What each file is

| File | Purpose |
| --- | --- |
| `flake.nix` | Entry point. Defines the `nixosConfigurations.nixos` output, pins `nixpkgs` to an exact revision, and wires in the `lanzaboote` (Secure Boot) and `home-manager` inputs. |
| `flake.lock` | Locks the resolved revisions of every flake input. Regenerated by `nix flake update`. |
| `configuration.nix` | The main file you edit. System packages, services, users, locale, desktop, bootloader, drives. |
| `hardware-configuration.nix` | Auto-generated by `nixos-generate-config`. Holds filesystem UUIDs and kernel modules. Do not edit by hand. |
| `home.nix` | home-manager config for user `blob` (direnv, git). Applied as part of the system rebuild. |
| `AGENTS.md` | Operational notes for AI agents editing this repo. `CLAUDE.md` is a one-line pointer to it. |

## Updating packages

`nixpkgs` is pinned to an exact revision in `flake.nix`, not tracked via `nix-channel`. A plain rebuild will not pull newer packages on its own. To move package versions:

```bash
# Update all flake inputs (nixpkgs, home-manager, lanzaboote).
nix flake update

# Or update a single input.
nix flake update nixpkgs

# Then rebuild.
sudo nixos-rebuild switch
```

To find a package name before adding it to `environment.systemPackages`:

```bash
nix search nixpkgs <name>
```

## Adding things

- System-wide packages go in `environment.systemPackages` (the `with pkgs; [ ... ]` block in `configuration.nix`).
- Per-user packages go in `users.users."blob".packages` when they are user-specific.
- Prefer `services.<name>.enable = true;` over hand-wiring systemd units. NixOS modules handle the dependencies and config files.
- When you add a **new file** to the flake (a new module, splitting out config), run `git add <file>` before rebuilding. Flakes only evaluate git-tracked files, so an un-added file fails with `path '...' does not exist`. Editing existing tracked files needs no re-add.

## Notable setup on this host

- **Secure Boot** via lanzaboote. Signing keys live outside the Nix store in `/var/lib/sbctl`. Stock `systemd-boot` is force-disabled because lanzaboote replaces it.
- **home-manager** integrated as a NixOS module (`useGlobalPkgs` + `useUserPackages`), so it shares the system nixpkgs and installs into `/etc/profiles`.
- **NVIDIA RTX 5070 (Blackwell)** using the open kernel modules (the only ones that support Blackwell), with VRAM-preserving suspend/resume power management.
- **Desktops:** GNOME on Wayland via GDM, plus Hyprland as a selectable session for fallback.
- **Audio:** PipeWire (ALSA + Pulse compat). PulseAudio is explicitly disabled.
- **Shared multi-boot storage:** the ESP and several `/mnt/*` drives are shared with Windows and another Linux install. The extra drives mount lazily via systemd automount with `nofail`, so a missing disk never blocks boot.
- `system.stateVersion = "26.05"` pins stateful defaults to the original install. Leave it alone.
