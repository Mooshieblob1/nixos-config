# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`/etc/nixos/` is the system-level NixOS configuration for a single machine (hostname `nixos`, primary user `blob`). It is not a software project — there are no builds, tests, or CI. Edits here change how the running OS is configured on the next rebuild.

This config is **flake-based**: `flake.nix` exposes `nixosConfigurations.nixos` (which imports `configuration.nix` plus the lanzaboote module). Because the flake lives at the default path `/etc/nixos/` and its name matches the hostname, `nixos-rebuild` auto-detects it — you do **not** need to pass `--flake`.

## Workflow

All changes flow through `nixos-rebuild`. After editing `configuration.nix`:

- `sudo nixos-rebuild switch` — apply the new config now and make it the default boot generation. (Auto-uses the flake; explicit form is `sudo nixos-rebuild switch --flake /etc/nixos#nixos`.)
- `sudo nixos-rebuild test` — apply without making it the default boot generation (use when unsure; reboot reverts).
- `sudo nixos-rebuild build` — evaluate and build without activating, useful for catching errors early.
- `sudo nixos-rebuild switch --rollback` — revert to the previous generation if something breaks.

To search for a package name before adding it to `environment.systemPackages`: `nix search nixpkgs <name>`.

`nixpkgs` is **pinned to an exact revision** in `flake.nix` (not tracked via `nix-channel`). To update the system's package set, bump the `nixpkgs.url` rev in `flake.nix` (and run `nix flake update` to refresh `flake.lock`) deliberately — a plain rebuild will not pull in newer packages on its own.

## File layout

- `flake.nix` — defines the `nixosConfigurations.nixos` output, pins `nixpkgs` to an exact rev, and wires in the `lanzaboote` input (secure-boot). Edit the `nixpkgs.url` rev here to move package versions.
- `flake.lock` — locks the resolved revisions of all flake inputs. Regenerate with `nix flake update` (all inputs) or `nix flake lock --update-input nixpkgs` (just one).
- `configuration.nix` — the file you'll normally edit. System packages, services, users, locale, desktop environment all live here.
- `hardware-configuration.nix` — auto-generated by `nixos-generate-config`; **do not edit**. Regenerate with `sudo nixos-generate-config` only if hardware changes (disks, CPU). Filesystem UUIDs and kernel modules are pinned here.

## Things already enabled (so you don't re-add them)

- Flakes + `nix-command` experimental features (`nix.settings.experimental-features`).
- Unfree packages allowed (`nixpkgs.config.allowUnfree = true`) — needed for `vivaldi`, etc.
- GNOME on Wayland via GDM; X11 server enabled with `au` keymap.
- PipeWire (with ALSA + Pulse compat); PulseAudio is explicitly disabled — don't re-enable it.
- NetworkManager for networking.
- `system.stateVersion = "26.05"` — leave this alone; it pins stateful defaults to the original install and changing it can break databases/state on disk.

## Conventions when editing `configuration.nix`

- Editing `/etc/nixos/*` requires `sudo` — the directory is root-owned. Stage edits in a temp path and `sudo install` / `sudo mv` them into place, or run the editor under sudo.
- Add system-wide packages to `environment.systemPackages` (the `with pkgs; [ ... ]` block). Add per-user packages to `users.users."blob".packages` instead when they're user-specific.
- Prefer the `services.<name>.enable = true;` style over manually wiring systemd units — NixOS modules handle dependencies and config files.
- After any edit, run `sudo nixos-rebuild test` first if the change touches the bootloader, display manager, or filesystems — a broken switch on those can leave the machine unbootable; `test` lets you reboot to recover.
